SpecReplay

Replays the real tool handlers of agentphone-mcp against a fake API built from its OpenAPI spec, to find places where the tools and the documented API disagree.

The problem

The project's history shows a run of contract-drift bugs between its MCP tools and the documented API: an empty 204 body failing output validation, documented null values rejected, a crash on a documented list shape, bounds dropped and later restored. The project's own check compares endpoint and field names. SpecReplay asks a different question: from the published spec alone, how many of those bugs would an automatic behavioural check have caught, and what does it flag today?

The ledger has 25 cases, 20 of them about contracts the spec documents. The rules were written knowing these cases, so the 20/25 figure shows the rules reproduce the history. It is not a rate for unseen drift.

What it flags at v0.10.0

12 documented findings come down to 5 root causes, one of which is already known. None is shown to break a user. The maintainers report in #88 that the API answers 422 to out-of-range values, so a missing client-side bound likely means a late 422. Nothing was run against the live API. The root causes and their code sites are listed under Technical details.

How it works

Inputs13 pinned commits, the OpenAPI spec, one fixture call per tool
Real handlersfetch replaced by a fake API built from the spec, one change at a time: null, omit, enum, 204
Findingscrash, error result, output schema, request, bound
Score25-case ledger and the hold-out

Each pinned commit's real tools.ts, api.ts and output-schemas.ts run with the zod version they pin. fetch is replaced by an in-process API that answers from the spec. Each tool is called once with a valid fixture, then again with one thing changed in the response: a nullable field set to null, an optional field left out, another enum value, an empty array, a 204. Requests are checked against the spec, and each argument that reaches a constrained request field is probed with a value just past the documented limit. Nothing touches the network or the live API.

Limits

  • 36 of 98 operations document an unconstrained response, so nothing can be judged there.
  • The handlers run against a stubbed fetch and an emulation of the SDK's three checks, not the SDK.
  • Single-fault mutations only. Combined faults are out of scope.
  • The spec is treated as correct. A spec error shows up as a tool bug.
  • The spec is a live document. The copy used for the committed results is not retrievable, and a later fetch differs in one description. The experiment still reproduces the results byte for byte.

Technical details

Method

A finding is documented when the operation it is about has a success response a tool can be judged against: no content, or a JSON schema with at least one key that is not an annotation. Findings on unconstrained operations stay in the reports but are left out of the findings count and the documented recall. A ledger case is caught when a matching finding exists at its buggy commit and none exists at its fix commit.

Hold-out

Three cases outside the ledger, with the rules frozen first (git tag rules-frozen) and predictions written before the first run. One caught, two missed with their bugs shown to be exercised. Three cases is too few for a rate. It shows which classes are covered.

Prompt wrapper

In hosted mode the tool wraps system_prompt in identity text. Wide mode measured this on the real handler: systemPrompt:maxLength added=528 threshold=19472. A plain ASCII prompt over that threshold would go out over the documented 20000. This is measured offline. Live behaviour is unverified.

What v2 changed

  • Findings are reported as root causes, not as counts of "new bugs" or "confirmed".
  • Recall is labelled in-sample, and a small frozen hold-out was added.
  • Wide mode probes arguments the fixtures leave out and measures the prompt wrapper.
  • Review fixes after the freeze did not move the 25-case results.

Full list: docs/V2-CHANGES.md.

Data and licenses

The code is MIT. Nothing from the projects studied is committed. tools/fetch_data.py rebuilds upstream/ and checks every file against the sha256 values in upstream/MANIFEST.json. The agentphone-mcp sources and the zod package are MIT and are fetched with their own licenses. The OpenAPI document carries no license, so it is never republished.

Reproduce

git clone https://github.com/yashgix/specreplay && cd specreplay
npm install --no-save typescript@7.0.2
export SPECREPLAY_NODE=/path/to/node22
python tools/fetch_data.py --accept-spec-drift
make test experiment

Two runs of the experiment produce byte-identical results.
