SpecDrift

Replays the real tool handlers of agentphone-mcp against a fake API built from its OpenAPI spec, to find places where the tools and the documented API disagree.

GitHub

The problem

The project's history shows a run of contract-drift bugs between its MCP tools and the documented API: an empty 204 body failing output validation, documented null values rejected, a crash on a documented list shape, bounds dropped and later restored. The project's own check compares endpoint and field names. SpecDrift asks a different question: from the published spec alone, how many of those bugs would an automatic behavioural check have caught, and what does it flag today?

Approach

Each pinned commit's real tools.ts, api.ts and output-schemas.ts run with the zod version they pin. fetch is replaced by an in-process API that answers from the spec. Each tool is called once with a valid fixture, then again with one thing changed in the response: a nullable field set to null, an optional field left out, another enum value, an empty array, a 204. Requests are checked against the spec, and each argument that reaches a constrained request field is probed with a value just past the documented limit. Nothing touches the network or the live API.

Prompt wrapper

In hosted mode the tool wraps system_prompt in identity text. Wide mode measured this on the real handler: systemPrompt:maxLength added=528 threshold=19472. A plain ASCII prompt over that threshold would go out over the documented 20000. This is measured offline. Live behaviour is unverified.

What v2 changed

  • Findings are reported as root causes, not as counts of "new bugs" or "confirmed".
  • Recall is labelled in-sample, and a small frozen hold-out was added.
  • Wide mode probes arguments the fixtures leave out and measures the prompt wrapper.
  • Review fixes after the freeze did not move the 25-case results.

Full list: docs/V2-CHANGES.md.

Limits

  • 36 of 98 operations document an unconstrained response, so nothing can be judged there.
  • The handlers run against a stubbed fetch and an emulation of the SDK's three checks, not the SDK.
  • Single-fault mutations only. Combined faults are out of scope.
  • The spec is treated as correct. A spec error shows up as a tool bug.
  • The spec is a live document. The copy used for the committed results is not retrievable, and a later fetch differs in one description. The experiment still reproduces the results byte for byte.
